# 比較ボードの閲覧

ホーム下部の「検査結果」の隣にある「メニュー」→「比較ボード（閲覧専用）」から開く。「更新」でGoogle認証後、PfcPlanBoardの保存済み比較ボードを取得する。初回以外は端末に保存した前回取得分を通信なしでも表示する。

## 接続条件

- PCで比較ボード・日次プランを保存し、Google Driveの同期を完了させる。画像もPC側で同期する。
- AndroidとPCで同じGoogleアカウントを使う。
- AndroidのOAuthクライアント（package名と署名SHA-1）を、PCのOAuthクライアントと同じGoogle Cloudプロジェクトに登録する。ソースだけではCloud Consoleの登録先を確定できない。
- Androidが要求する追加scopeは `https://www.googleapis.com/auth/drive.appdata`。このscope自体は書込みも許可するが、本閲覧機能の通信コードはGETだけを実装する。
- DatasetIdはPCの既定値 `9b0db1ba-7ee0-4cf3-9b9b-84f674a8d1bb`。異なるDatasetIdのデータは読まない。

一覧が空でも、PCにデータが存在しないとは断定できない。別アカウント・別OAuthプロジェクト・PCの未同期でも同じ結果になる。権限の追加だけを接続成功の根拠にしない。

Google公式資料: [appDataFolder](https://developers.google.com/workspace/drive/api/guides/appdata)、[AndroidのGoogle認証](https://developer.android.com/identity/authorization)。

## 復元とデータ保全

- 完成済みJSONを想定せず、ページ送りした一覧から対象DatasetIdのバッチ全履歴を取得する。ProtocolVersion=1を受け入れる。
- EFの完全EntityType名・PascalCaseのスカラー列から関連行を復元。RevisionはUTC ticks、DeviceId、DeviceSequence、OperationIdの順で比較。削除も同じ比較で反映し、BatchId・OperationIdの重複を除外する。
- 全履歴は1バッチずつ処理し、現在状態を再構築する。過去のバッチ全体を一度にメモリへ保持しない。毎回全履歴から新たに復元するため、再更新で食事やプランが重複しない。
- 取得・復元が失敗した場合、前回取得分を保持する。空の同期一覧でもキャッシュを消さない。正しく取得できた履歴にボードが存在しない場合は「比較ボードなし」を表示する。
- ボード・プラン・食事・食品/料理の参照画像をSHA-256で検証する。未同期画像はプレースホルダーと件数で示す。
- 端末の `noBackupFilesDir/pfc-viewer` に復元した現在状態と画像を保存。Windowsの画像パスは保存しない。認証情報・トークンは保存せず、同期内容・APIエラー本文をログへ出さない。
- PCの同期Coordinator、送信キュー、更新・削除APIは移植しない。追加のサーバー、同期基盤、ライブラリは不要。

## 計算と表示

- ボードに保存された計算モード（Standard=0、HIGH=1、LOW=2）を使用。
- kcalは0.1 kcal整数、PFCはmg整数のPC表現と、数量換算・各段階の丸めを合わせる。表示はkcal整数、PFC小数1桁、プリン体mg小数1桁。
- 食前飲料は朝・昼・夕に含め、日次合計では3回分。差分の方向は比較プラン−基準プラン。
- 日次差分は丸め前の栄養値から計算。食事差分はPCと同じく表示値に丸めた後で差し引く。
- Androidでの基準プラン・閲覧プランの選択は端末表示だけに使用。PCの選択タブ・展開状態には書き戻さない。

## 接続後の確認

1. PCとAndroidで同じボードを開き、プラン順・食事・画像・各計算モードの栄養値を照合する。
2. 同じ基準プランを選び、日次および朝昼夕の差分を照合する。
3. 2回更新して重複しないことを確認する。PCで変更・削除して同期後、再取得で反映されることも確認する。
4. 通信不能時に前回取得分が残ることを確認する。

合成データのテストは実データ・実機OAuth接続の代替にはならない。接続未確認の場合は上記を残件として扱う。

## 今回の確認結果（2026-10-19）

- `gradlew.bat :app:assembleDebug :app:testDebugUnitTest --tests '*PfcSyncSnapshotTest' --tests '*PfcBoardProjectionTest'` 成功。復元8件、栄養・比較8件の計16件成功。
- 接続実機へデータを保持して上書きインストール。「メニュー」→比較ボード→更新の導線と、対象同期データがない場合の表示を確認。
- `drive.appdata` のトークンでDrive一覧取得は成功したが、対象バッチは0件。PCの実際のidentityのDatasetIdは指定値と一致。Google公式tokeninfoでAndroidのOAuthプロジェクト番号を追加診断し、PC設定の `161391359542`（`pfcplanboard-sync`）に対し、Androidは `940065627125` と確認。OAuthプロジェクト不一致を特定した。PC側の認証情報は移植していない。
- 実データの表示・PCとの数値/画像一致、実データ取得後の再更新および通信失敗時の表示保持は実機未確認。履歴復元・重複・削除・単位換算・丸めは合成データで確認。

## 取得できない場合の対応

今回の原因は、PCとAndroidのOAuthプロジェクト不一致。PCの保存先を維持するため、Android用OAuthクライアントの登録をPCの `pfcplanboard-sync` へ揃える。Cloud ConsoleのGoogle Auth Platform→クライアントで、種類Android、package `com.goenc.healthsheetsync`、現在のAPKの公開証明書SHA-1を指定する。PCのデスクトップ用クライアントJSONをAndroidへ入れない。

同じpackage/SHA-1の組は別プロジェクトへ重複登録できない場合がある。旧プロジェクトの該当Androidクライアント設定を控えたうえで、対象クライアントだけを移設する。プロジェクト全体、PCのデスクトップクライアント、Driveデータは削除しない。既存のSheets連携も新プロジェクトで再同意が必要になる可能性がある。

既存の検査結果・スプレッドシート連携を維持するため、移設先プロジェクトのGoogle Sheets APIも有効か確認し、無効なら有効化する。Drive APIはPCの同期に使用中。Google同意画面がテスト中なら、PCとAndroidで使うアカウントをテストユーザーへ含める。

登録変更後、Androidを終了して開き直し、比較ボードの「更新」でPCと同じGoogleアカウントを選び権限に再同意する。PC側では通常の同期を完了させる。アプリのデータ消去・アンインストールは不要。反映確認では、空一覧時に表示するAndroid OAuthプロジェクト番号がPC側と一致することを確認する。

根拠: [Google公式のtokeninfo診断](https://docs.cloud.google.com/docs/authentication/token-types)、[Android OAuthクライアント設定](https://support.google.com/googleapi/answer/6158849)、[package/SHA-1重複登録](https://support.google.com/firebase/answer/6401008)。
