# 検査結果の保存と閲覧

## 項目と結果の分離

検査データの通常の読み書きは端末内の `lab_results.db`（SQLite）で完結する。Google Sheetsは即時反映するバックアップ先。アプリ起動・通常表示・取り込み後の表示ではSheetsから検査データを取得しない。検査設定内の「更新」を押した時だけ、Sheetsを検証してSQLiteへ反映する。

- `lab_items`: 項目IDを主キー、項目名を一意とし、単位と初期基準範囲を保持。
- `lab_results`: 検査日と項目IDを複合主キーとし、項目IDは `lab_items` への外部キー。結果値と比較記号を保持。
- `lab_reference_ranges`: 項目IDを主キー・外部キーとし、利用者が設定した上下限、境界を含めるか、高低判定の無効化を保持。
- `lab_metadata`: 保存・取得時刻、旧キャッシュ・旧設定の移行済み情報、バックアップの保存世代と反映済み世代。

SQLiteの外部キー制約を有効化し、存在しない項目への結果登録・同日同項目の重複・参照中の項目削除を拒否する。取得データの検証失敗時は既存の結果を保持する。Sheets自体にはDB制約がないため、読み込み・保存時にもID・重複・値形式を検証する。Sheetsを直接編集した内容や他端末の変更を利用する場合は、アプリで保存する前に「更新」で取り込むこと。バックアップは端末内DBを正本として同じ位置へ書き戻すため、保存前に取り込んでいないSheets側の変更は上書きされる場合がある。

## 血液検査・体組成のタブ

「検査結果」を「血液検査」「体組成」の2タブで表示する。血液検査には以前の検査結果を保持し、尿検査なども除外しない。体組成は直近1～3回の測定値を比較し、前後ボタン・横スワイプで測定期間を移動する。項目を押すと日時別の履歴と推移グラフを開く。表示項目・比較回数は血液検査と体組成で別々に保存する。

両タブは中央の年表示と「前へ／次へ」の配置・向きを共有し、比較列は月を表示する。体組成の同月複数測定では日を補足し、同日複数測定では時刻も表示する。履歴の日付は血液検査と同じ `YYYY-MM-DD`、グラフの日付は `yyyy/M/d` を使う。体組成の基礎代謝量は一覧・履歴・設定・取り込み確認で `kcal` と表示する。保存・同期用の `kcal/日` は維持する。

体組成の対象は体重、着衣量、体脂肪率、脂肪量、除脂肪量、筋肉量、体水分量、体水分率、推定骨量、基礎代謝量、体内年齢、内臓脂肪レベル、脚点、BMI、標準体重、肥満度。後ろの3項目は「対象項目」では初期非表示。身長は取り込み時に除外する。体重と着衣量は測定票の値を別々に保存し、自動で加減せず、通常の体重記録にも反映しない。未測定は「—」、1回の測定はグラフの1点として表示する。機器・出所・単位が異なる系列は切り替えて表示し、高低判定は行わない。

体組成計の体脂肪率・基礎代謝量・BMIは測定票の記録として保持し、既存の推定体脂肪率、消費カロリー設定、指数計算へ自動反映しない。

### 体組成の保存と取り込み

SQLite version 3で、既存の検査表を保持したまま次の表を追加する。version 1からは既存の表示順移行も順番に実施する。

- `body_measurements`: UUIDの測定ID、測定日、時刻（不明ならNULL）、機器名、出所（photo/manual/csv）。
- `body_values`: 測定ID、固定項目ID、検証済み10進文字列、単位。測定IDと項目IDを複合主キーとし、測定表への外部キーを持つ。

測定日時は用紙の記載を使い、撮影日・現在日・不明な時刻を補完しない。写真解析はChatGPT共有方式で、アプリ内OCRは行わない。指示文はクリップボードにもコピーするため、ChatGPTに表示されない場合は貼り付ける。体組成設定から写真を共有し、返された次の形式を取り込む。値と単位は文字列で指定する。

```json
{"type":"bodyComposition","measurements":[{"targetDate":"2026-01-02","measuredTime":"09:00","deviceModel":"試験機","source":"photo","values":[{"metricId":"bodyFatPercent","value":"20.0","unit":"%"}]}]}
```

項目IDと標準単位は `BODY_COMPOSITION_METRICS` が定義する。用紙の基礎代謝量の `kcal` は `kcal/日` に正規化する。未知の項目、単位違い、非数値、同一測定内の項目重複は拒否する。確認画面で日時・機器・値・単位の修正、測定や項目の除外が可能。同じ日時・機器・項目値の再取り込みは、生成された測定IDや小数末尾の違いにかかわらず除外する。値の相違や、時刻・機器が不明で同日測定を区別できない場合は競合として保存を止める。異なる既知時刻の同日測定は別々に保存する。

確認画面で全項目が一致する同一測定は、重複のため追加がないことを緑色で表示する。日時・機器が一致する測定との相違は、確認画面と修正画面で該当項目を赤く表示し、登録済みまたは同時に取り込む別の測定の値を併記する。今回の結果にない比較対象の項目も確認画面に表示する。複数候補や日時・機器不明で比較対象を特定できない場合は、値の誤りと断定せず日時・機器の確認を促す。

既存の測定に体重・着衣量を補完する場合、日時と機器が明確に一致し、共通する項目が1件以上あり、その値と単位が一致するときだけ不足分を追加する。両方とも時刻不明の場合は、同日・同機器・同じ出所の候補が1件で、3項目以上ある既存値がすべて一致する場合に限り、同一の測定か確認画面で注意を示してから補完できる。既存値は上書きせず、時刻も補完しない。古いバージョンは追加した項目を読み取れないため、別端末も更新してから同期する。

Sheetsの `bodyMeasurements` は `measurementId,targetDate,measuredTime,deviceModel,source` の5列、`bodyValues` は `measurementId,metricId,value,unit` の4列。初回の体組成バックアップで専用シートを作成する。検査・体組成の全表とシート追加を1回の `spreadsheets.batchUpdate` で反映し、古い末尾行も消去する。正常応答後だけ送信世代を反映済みにする。通信失敗時はローカルの値と未反映世代を保持し、「更新」で再試行する。

体組成シートが両方存在しない旧ブックは読み込み可能で、ローカルの体組成を消さない。片方だけ存在する場合や参照不整合がある場合は、既存データを置換せずエラーにする。片方の端末を旧バージョンのまま使って新しい体組成データを書き戻す運用は避け、端末を切り替える際は更新後にSheetsを取り込む。

数値は精度と小数の末尾を保つため、検証済み10進文字列として保存する。単位は結果値に含めない。「5.0未満」は値 `5.0` と比較記号 `<` に分離し、「(-)」などの定性検査は文字結果として保持する。

## 項目設定

検査結果一覧から項目を押し、履歴画面の「項目設定」で単位・基準範囲を設定する。一度保存すれば、その項目の全日付と今後の取り込みに共通適用する。

- 上下限は片側だけでも可。境界値を正常範囲に含めるかも指定可能。
- 単位と基準範囲の利用者設定は端末内SQLiteに保存。更新やアプリ再起動で上書きしない。
- 過去データに一致する基準範囲がある場合だけ初期設定する。複数基準・解析不能な基準は推測せず設定を求める。
- 項目マスターの `initialReferenceRange` は移行・新端末の初期設定用。保存済みの基準範囲を変更しない。
- 設定した数値基準で一覧・履歴・グラフを共通判定する。「未満」や定性値の高低は推測しない。
- 設定保存の直後、単位と基準範囲もSheetsへ反映する。アプリのデータ削除・アンインストールで端末内設定は失われるが、反映済みの設定は「更新」で初期復元できる。保存済みのローカル設定は上書きしない。

## 写真からのJSON取り込み

項目設定一覧の写真共有ボタンで、検査票と読み取り用プロンプトをChatGPTへ渡す。出力は `targetDate`・`itemName`・`value` の3キーだけを持つJSON配列。単位・基準範囲・高低表示は出力させない。数値も文字列で受け取り、小数の末尾を保持する。

「取り込み」でJSONを貼り付け、確認画面で結果を修正または除外する。端末内DBで同日同項目の同一値は除外、相違は上書きせず確認を求める。既存項目名はマスターの項目IDへ解決し、新規項目だけマスターを追加する。結果とバックアップ待ちの世代を同じDBトランザクションで保存し、その直後にGoogle認証してSheetsへ反映する。保存前後にSheetsの検査データは取得しない。コードフェンス付きJSONと以前の6キーJSONも読み込めるが、旧形式の付加情報は取り込まない。

通信・認証失敗でもDB保存を取り消さない。Sheets未反映を画面に表示し、反映待ちの世代を再起動後も保持する。次の保存または「更新」で再送する。「更新」は未反映データを先にバックアップしてから取得し、ローカル保存の消失を防ぐ。同じ位置へ同じDBスナップショットを書き戻すため、応答だけ失われた場合も再送で重複しない。送信した世代だけ反映済みにし、送信中の新しい変更は次の反映対象に残す。

## Google Sheetsの構成

保存先は `SpreadsheetUploadSettings.TARGET_SPREADSHEET_ID` の既存ブック。

### labItems

| 列名 | 内容 |
| --- | --- |
| itemId | 項目の固定ID。主キー相当 |
| itemName | 検査項目名。一意 |
| unit | 項目共通の単位。単位なしは空欄 |
| initialReferenceRange | 一致する旧基準範囲。端末初期設定用 |

### labResults

| 列名 | 内容 |
| --- | --- |
| targetDate | YYYY-MM-DDの検査日 |
| itemId | labItemsの項目ID。外部キー相当 |
| value | 数値だけの10進文字列、または定性検査の文字結果 |
| valueQualifier | 数値は `=`・`<`・`<=`・`>`・`>=`、文字結果は `text` |

結果には項目名・単位・基準範囲・高低判定を繰り返し保存しない。日付と項目IDの組を一意に保つ。全月を同じ形式で管理する。

### labReferenceRanges

`itemId`、`minimum`、`maximum`、`minimumInclusive`、`maximumInclusive`、`disabled` の6列。項目IDを一意の参照キーとし、上下限と境界・無効化設定をバックアップする。上下限なしは空欄、境界を含む場合と無効化は1、それ以外は0。

## 旧データからの移行と保全

移行前の6列Sheetsは非表示のバックアップタブへ複製し、元の値・単位・基準範囲・判定を保持する。既存結果の値と日付、項目の対応を確認してから項目マスターと正規化結果へ移す。

旧 `lab_results_cache.json` とSharedPreferencesの項目別基準範囲は、初回起動時にSQLiteへ移行する。移行完了はDBに記録し、次回起動では古いキャッシュで上書きしない。旧キャッシュ・旧設定自体は保全する。

通常の体重等のミラー同期は検査テーブルを置換しない。検査用の専用処理でDB保存済みデータを反映する。画面はSQLiteを使用し、通信失敗時もDB保存済みの結果を表示する。
