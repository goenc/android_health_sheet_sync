# 検査結果の保存と閲覧

## 項目と結果の分離

検査データは端末内の `lab_results.db`（SQLite）で管理する。Google Sheetsは項目と結果の共有保存先。取得時に両テーブルを検証し、SQLiteへ1トランザクションで反映する。

- `lab_items`: 項目IDを主キー、項目名を一意とし、単位と初期基準範囲を保持。
- `lab_results`: 検査日と項目IDを複合主キーとし、項目IDは `lab_items` への外部キー。結果値と比較記号を保持。
- `lab_reference_ranges`: 項目IDを主キー・外部キーとし、利用者が設定した上下限、境界を含めるか、高低判定の無効化を保持。
- `lab_metadata`: 取得時刻と旧キャッシュ・旧設定の移行済み情報。

SQLiteの外部キー制約を有効化し、存在しない項目への結果登録・同日同項目の重複・参照中の項目削除を拒否する。取得データの検証失敗時は既存の結果を保持する。Sheets自体にはDB制約がないため、アプリの読み込み・保存時にもID・重複・値形式を検証する。同時に複数端末から同じ結果を保存した場合の競合は次回取得時に検出される。Sheetsを直接編集する場合も同じ規則を守ること。

数値は精度と小数の末尾を保つため、検証済み10進文字列として保存する。単位は結果値に含めない。「5.0未満」は値 `5.0` と比較記号 `<` に分離し、「(-)」などの定性検査は文字結果として保持する。

## 項目設定

検査結果一覧から項目を押し、履歴画面の「項目設定」で単位・基準範囲を設定する。一度保存すれば、その項目の全日付と今後の取り込みに共通適用する。

- 上下限は片側だけでも可。境界値を正常範囲に含めるかも指定可能。
- 単位と基準範囲の利用者設定は端末内SQLiteに保存。更新やアプリ再起動で上書きしない。
- 過去データに一致する基準範囲がある場合だけ初期設定する。複数基準・解析不能な基準は推測せず設定を求める。
- 項目マスターの `initialReferenceRange` は移行・新端末の初期設定用。保存済みの基準範囲を変更しない。
- 設定した数値基準で一覧・履歴・グラフを共通判定する。「未満」や定性値の高低は推測しない。
- アプリのデータ削除・アンインストールでは端末内設定が失われる。Sheetsへ設定の自動同期は行わない。

## 写真からのJSON取り込み

項目設定一覧の写真共有ボタンで、検査票と読み取り用プロンプトをChatGPTへ渡す。出力は `targetDate`・`itemName`・`value` の3キーだけを持つJSON配列。単位・基準範囲・高低表示は出力させない。数値も文字列で受け取り、小数の末尾を保持する。

「取り込み」でJSONを貼り付け、確認画面で結果を修正または除外する。保存直前にSheetsを再取得し、同日同項目の同一値は除外、相違は上書きせず確認を求める。既存項目名はマスターの項目IDへ解決し、新規項目だけマスターを追加する。項目追加と結果追記は1回のSheets batchUpdateでまとめて保存する。コードフェンス付きJSONと以前の6キーJSONも読み込めるが、旧形式の付加情報は取り込まない。

## Google Sheetsの構成

保存先は `SpreadsheetUploadSettings.TARGET_SPREADSHEET_ID` の既存ブック。

### labItems

| 列名 | 内容 |
| --- | --- |
| itemId | 項目の固定ID。主キー相当 |
| itemName | 検査項目名。一意 |
| unit | 項目共通の単位。単位なしは空欄 |
| initialReferenceRange | 一致する旧基準範囲。端末初期設定用 |

### labResults

| 列名 | 内容 |
| --- | --- |
| targetDate | YYYY-MM-DDの検査日 |
| itemId | labItemsの項目ID。外部キー相当 |
| value | 数値だけの10進文字列、または定性検査の文字結果 |
| valueQualifier | 数値は `=`・`<`・`<=`・`>`・`>=`、文字結果は `text` |

結果には項目名・単位・基準範囲・高低判定を繰り返し保存しない。日付と項目IDの組を一意に保つ。全月を同じ形式で管理する。

## 旧データからの移行と保全

移行前の6列Sheetsは非表示のバックアップタブへ複製し、元の値・単位・基準範囲・判定を保持する。既存結果の値と日付、項目の対応を確認してから項目マスターと正規化結果へ移す。

旧 `lab_results_cache.json` とSharedPreferencesの項目別基準範囲は、初回起動時にSQLiteへ移行する。移行完了はDBに記録し、次回起動では古いキャッシュで上書きしない。旧キャッシュ・旧設定自体は保全する。

通常の体重等のミラー同期は検査テーブルを置換しない。検査画面で確認した結果だけを専用保存処理で追記する。画面はSQLiteの取得済みデータを使用し、取得失敗時も以前の結果を表示する。
