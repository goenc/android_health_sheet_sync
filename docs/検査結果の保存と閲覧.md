# 検査結果の保存と閲覧

アプリの「検査結果」を開くと、許可済みのGoogleアカウントでGoogle Sheetsから取得する。認証が必要な場合は歯車から検査結果の設定画面を開き、「更新」から認証する。
検査結果の設定画面の「更新」でChatGPTが追加した結果を再取得する。戻ると元の検査日・項目別画面へ戻る。
月見出しの左にある「全項目」「対象項目」で表示を切り替える。設定画面でチェックした項目だけを対象項目として表示する。選択と表示モードは端末内へ保存する。初期状態と新しく取得した項目はチェック済み。全項目ではチェックに関係なくすべて表示し、チェックを外しても元の検査結果は削除しない。同名項目の単位が異なる場合もまとめて選択する。
検査日と履歴一覧は新しい日付順に固定。直近2回の検査結果を左右に並べ、上部は表示中の新しい検査日の年、数値列の見出しは先頭の0を省いた月を表示する。同じ月の検査も別の列として扱う。1回分だけの場合は右列を空欄にする。
日付別の表を左へスワイプすると古い2回分へ、右へスワイプすると新しい2回分へ移動する。「前へ」「次へ」も2回分ずつ移動する。詳しい検査日は項目別履歴で確認できる。
日付別一覧は取得済みの全検査日で確認できた項目を共通の順番で表示し、その日に検査されていない項目は「—」にする。同じ項目の既存単位が一種類だけなら、単位なしで取り込んだ記録も同じ比較行に表示する。表示用の単位補完だけを行い、保存済みの単位や新しい記録の基準範囲・高低表示は変更しない。既存単位が複数ある場合は異なる単位の結果を統合しない。
未検査の行は表示専用。別の日付の値・基準範囲・高低判定は流用せず、保存データや推移グラフにも追加しない。
「前へ」「次へ」でも移動できる。先頭・末尾ではそれ以上移動しない。項目をタップすると同名項目の全日付の履歴を表示する。
項目別画面の上部に推移グラフ、下部に日付・数値の一覧を表示する。グラフは古い日付から新しい日付へ、実際の日付間隔で描く。
グラフの点または一覧の行をタップすると、対応する点と行を強調する。単位が異なる記録は単位を選んで切り替える。
定性値、不明値、不等号付きの値は数値へ推測変換せず、一覧に原文を残す。点が一つ、または全点同じ値でも描画する。
結果は1項目1行とし、単位は項目名の直後に小さく表示する。未検査の行も項目の単位を維持する。基準範囲は項目別画面の各検査日の行に表示する。高値は↑と数値を赤色、低値は↓と数値を青色で示す。項目別グラフの高値の点は赤色、低値の点は青色で表示する。
取得済み結果は端末内に保存する。取得日時・件数・状況はメイン画面の設定内に表示する。
通信・認証・形式エラー時は前回の結果を残し、検査結果画面にもエラーを表示する。

## ChatGPTからの登録

検査結果の設定画面の下部に「写真をChatGPTで解析」と「検査結果を取り込む」を配置する。

1. 「写真をChatGPTで解析」で検査票の写真を選ぶ。複数枚も選択できる。
2. 既存項目名と固定の出力形式を含む解析指示を画像とともにChatGPTへ共有する。解析指示はクリップボードにもコピーする。ChatGPTで本文が入らない場合は貼り付けて送信する。
3. ChatGPTが返すJSONコードブロックのコピーボタンでコピーしてアプリに戻り、「検査結果を取り込む」の貼り付け画面へ貼り付ける。解析指示は1項目1行、余分な字下げなし、閉じ括弧まで完全な配列を出す形式を指定する。ChatGPT側で表示・生成が欠ける場合は、回答をコピーして配列末尾まであるかを確認し、必要に応じて新しいチャットで再送する。コードブロック指定だけでChatGPT側の不具合の解消は保証しない。
4. 「内容を確認」で検査日・項目・値を確認する。項目を押すと修正・除外できる。
5. 「確認した結果を保存」でGoogle認証後に`labResults`へ追記する。保存済みの同一結果は除外し、相違のある同日・同項目は上書きせず修正または除外を求める。

出力は`targetDate`、`itemName`、`value`の3キーだけを持つJSONオブジェクトの配列。値はすべて文字列。単位・基準範囲・高低表示は出力・取り込み対象にしない。以前の6キー形式も読み込めるが、付加情報は取り込まない。コードフェンス付きのJSONも貼り付け可能。必須値、日付、形式に問題がある場合は保存しない。読めない値や検査日が不明な項目は推測で生成せず、原票を確認する。

既存結果との一致判定も検査日・項目名・値の3項目で行い、同じ値なら既存行を保持して除外する。保存先の6列構成は維持し、新しく追記する行の単位・基準範囲・高低表示は空欄とする。項目別履歴では、既存単位が一種類だけなら単位なしの新しい記録も同じグラフへ表示する。複数の既存単位がある場合は従来どおり区別する。

保存直前にもGoogle Sheetsの最新値と重複・相違を確認する。既存列の並べ替えに合わせてRAW形式の文字列を追記し、既存行を変更・削除しない。必須列が不足する場合は保存を止める。追記後の再取得が失敗した場合は保存済みと表示し、「更新」で再取得する。

保存先は `SpreadsheetUploadSettings.TARGET_SPREADSHEET_ID` の既存ブック。専用タブ名は `labResults`。
1行目は次の列名、2行目以降は1行につき1日・1項目の結果。3月以前や別年の結果も同じ形式で追加できる。

| 列名 | 内容 |
| --- | --- |
| targetDate | 検査日。YYYY-MM-DDの文字列。必須 |
| itemName | 検査項目名。履歴比較のため同じ項目は同じ名前。必須 |
| value | 数値または `(-)`、`(+-)` などの文字列。必須 |
| unit | 単位。単位のない定性検査は空欄 |
| referenceRange | その検査票に記載された基準値。未記載は空欄 |
| flag | 検査票に↑がある場合H、↓の場合L。それ以外は空欄 |

登録時は既存の検査日・項目名を確認し、同じ結果を重複追加しない。
日付はRAW入力かプレーンテキスト形式を使う。数値の桁・小数の末尾を保持したい場合、valueも文字列として入力する。
読めない数値・検査票の空欄は推測で埋めない。検査票に記載された基準値・矢印だけを転記し、アプリは独自の医学的判定をしない。
検査日・項目名・値の欠落や不正な日付は、行番号付きのエラーにする。列の並べ替えと任意列の省略には対応する。
アプリが読むのはA～F列。6列の範囲内で並べ替えること。

## データ保全

`labResults` はGoogle Sheetsを正本とする。通常の携帯側ミラー同期では読み取り専用として保護し、検査結果の取り込み画面で利用者が確認した結果だけを追記する。
既存の携帯→Sheets同期の置換対象に含めないため、体重等の同期で検査結果は消えない。
患者名・カルテ番号・実際の検査値・画像はソースやGitへ保存しない。
過去の検査票が追加で提供されるまで、未提供の月の値は空のまま。

Google SheetsはコネクターのAPI読み戻しで確認。利用者のGoogleアカウントを使ったアプリ内の認証・ネットワーク取得と実機表示は未確認。
